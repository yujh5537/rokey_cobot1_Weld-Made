---
name: start-issue
description: GitHub 이슈 번호를 받아 작업을 시작한다. 이슈를 읽고, 관련 계약 문서를 확인하고, 브랜치를 만들고, 구현 계획을 제시한다. "이슈 #N 작업해줘", "T13 시작" 같은 요청에 사용한다.
---
1. `gh issue view <번호>`로 본문을 읽는다. "수정 범위", "완료 조건", "BRD 근거"를 확인한다.
2. 이슈가 가리키는 docs만 읽는다(CLAUDE.md의 문서 표 참고). BRD는 근거로 적힌 절만 읽는다.
3. `git fetch origin && git switch -c t<ID>-<설명> origin/main`으로 브랜치를 만든다.
4. 코드를 쓰기 전에 계획을 보여준다: 바꿀 파일, 추가할 테스트, 계약과 어긋나는 점, 실기에서만 확인 가능한 항목.
5. 계획에 수정 범위 밖 파일이 있으면 그 사실을 먼저 말하고 사람의 확인을 받는다.
6. 사람이 승인하면 구현한다. 실기 확인이 필요한 항목은 실행하지 말고 체크리스트로 남긴다.
