## 안전
- 입회 1 명이 비상정지 손잡이를 잡는다. 모든 이동은 **10 mm/s**, 먼저 자세 **위 30 mm** 로 간 뒤 내려간다(스크립트가 그 순서다).
- 45° 자세는 1차에서 한 번도 안 해 본 자세다. 첫 자세(L0 start)는 Virtual 에서 먼저 돌려 오류가 없는지 본다.
- 실기에서 `success=false`(관절 한계 · 특이점)가 나오면 그 자세는 넘어간다. 억지로 조그로 만들지 않는다 — 대신 아래 "막힐 때" 절차.
- 과대 외력 정지 · 충돌 뒤에는 `units-frames.md` "이벤트 점검"(기준점 재접촉)을 한다.

- 세로선 bottom(z 104.13)은 작업대 + 테이프 2 + 여유 5 + 스탠드오프 수직 성분 2.12 다. **손가락이 작업대에 닿을 위험이 가장 큰 자세**다. 위 30 mm 에서 눈으로 보고 내려간다.
- **막힐 때**: ① 그 자세에서 툴 축 둘레로만 J6 를 ±30° · ±60° 돌려 되는 각을 찾고 posj 를 적는다(→ 파라미터 `tool_roll_deg` 후보). ② 전부 막히면 `--tilt 30` 으로 다시 돈다(`tilt_deg` 는 파라미터다). ③ 그래도 안 되면 그 선을 시연에서 빼는 것도 답이다 — 어느 선인지만 적는다.
- **판정 기준**: 16 자세 중 되는 자세 수와 막힌 자세의 원인(관절 한계 / 특이점 / 간섭). 간섭 최소 거리 < 10 mm 면 `standoff_m` 을 올리거나 `approach_m` 경로를 바꾼다(P2 에 전달).

## M4. 경유점 이동 방식 (학민)
`ExecutePath`(P1)를 `move_spline_task` 한 번으로 할지 `move_line` 반복(radius blend)으로 할지 정한다. **큐브 위 100 mm 공중**에서 지그재그 11 점(진행 4 mm 간격 · 좌우 ±2 mm), 10 mm/s. 자세는 수직(홈 자세) 그대로.

| 방식 | 서비스 success · 응답 지연 | 점 사이에서 멈추나 | `get_robot_state` MOVING 유지 | `move_stop` 즉시 정지 | 마지막 점 오차 (mm) | 판정 |
|---|---|---|---|---|---|---|
| `move_spline_task` ASYNC (`pos` = Float64MultiArray ×11, `pos_cnt` 11, `opt` 0 → 1 도 시도) | | | | | | |
| `move_line` ×11 ASYNC 연속 호출, radius 2 mm | | | | | | |
| `move_line` ×11 SYNC, radius 0 (정지 허용) | | | | | | |

- Virtual 에서 먼저(에뮬레이터가 `move_spline_task` 를 받는지). 실기에서 한 번은 본다 — 에뮬레이터와 다를 수 있다.
- 결과를 `docs/env/api-check-log.md` 에 [E-번호] 로 적는다(성공 · 지연 · 비고).
- 하나라도 "점 사이에서 안 멈추고, move_stop 이 듣고, 오차 ≤ 3 mm" 면 그것으로 P1 을 간다. 전부 멈추면 정지 허용(D8)으로 간다.
