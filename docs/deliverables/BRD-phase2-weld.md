# 1. 비즈니스 목표

## 1.1 1차에서 이어지는 것
1차 BRD 1.2절의 공정 흐름에서 ⑤ 용접은 "MVP 이후 — 경로 후보를 마커로 따라 그리는 시연 검토"(US-08, Could)였다. phase 2 는 이 단계를 한 걸음 더 구체화한다: 스캔이 만든 직육면체의 **모서리 8 개**(윗면 4 변 + 세로 4 모서리)를 **용접 토치를 흉내 낸 자세(두 면 이등분, 45° 기울임)** 와 **위빙**으로, 부재에 **닿지 않고** 따라간다.

| 단계 (1차 BRD 1.2) | 1차 MVP | phase 2 |
|---|---|---|
| ② 접촉 탐색 · ③ 형상 생성 | 5 점 → 직육면체 · 외곽 엣지 · 경로 후보 4 | 그대로 쓴다. 결과 파일(`result.json`)이 phase 2 의 입력이다 |
| ⑤ 용접 | 하지 않음 | **용접 모션까지.** 이음선 8 개 · 45° 자세 · 스탠드오프 3 mm · 지그재그 위빙. **아크 · 용접기는 없다** |
| ④ 관제 · 승인 | 3D · 버튼 · 로그 | 같은 화면에 8 선 · 현재 선 · 완료 선 · 탐침 궤적 · 진행률(D9) |

## 1.2 왜 하는가
- 1차 BRD 의 가설은 "품종 교체 시 재티칭이 가장 큰 운영 비용"이다. 1차는 형상 좌표를 교시 없이 얻는 데까지였고, **그 좌표로 로봇이 실제 작업 경로를 만들고 움직일 수 있는지**는 보이지 않았다. phase 2 는 스캔 → 경로 생성 → 실행을 한 번에 이어, 교시가 필요 없는 흐름이 끝까지 닫히는지를 실증한다.
- 경제성 수치(1차 BRD 1.6)는 바꾸지 않는다. phase 2 가 없애는 것은 그 산식의 "1회 재티칭 시간" 중 **경로 교시 몫**이지만, 그 몫을 따로 재지 않았으므로 새 수치를 만들지 않는다.

## 1.3 정직한 한계 (1차 BRD 1장 첫 문단과 같은 원칙)
- 단일 직육면체의 모서리는 **두 부재 사이의 실제 용접 이음이 아니다.** phase 2 의 "용접선"은 모서리를 이음선으로 **가정**한 것이다.
- 실제 아크 · 용접기 연동 · 용접 조건 · 비드 품질은 다루지 않는다. 탐침 팁이 토치 끝 자리를 대신한다.
- 결과의 확인 수준은 2026-09-27 기준 **Virtual(에뮬레이터) + 9/23 자세 도달성 실측**까지다. 실기 주행은 2026-09-29 1 회 예정이다.

# 2. 범위

## 포함 범위 (phase 2)
- 입력: 1차 스캔 결과(`result.json`, `scan_id` "" = 가장 최근 성공 결과, D5). 다시 스캔하지 않는다.
- 대상: 직육면체 모서리 8 선 — 윗면 L0~L3(루프) → 세로 L4~L7(위 → 아래). `start_line` ~ `end_line` 으로 일부만 할 수 있다(D28).
- 자세: 툴 축이 두 면 법선의 이등분면 안에서 연직에서 `tilt_deg`(출발값 45°) 기운다(D1 · D3). 선별 롤 `tool_roll_deg[8]`(D24).
- 스탠드오프: 팁 구 표면 ↔ 이음선 최단거리 `standoff_m`(출발값 3 mm). **힘 · 순응 제어를 켜지 않는다**(D2 · D22).
- 위빙: 진행 방향에 수직인 지그재그 경유점(출발값 진폭 2 mm · 반주기 4 mm), robot_manager 의 `ExecutePath` 로 지난다(D19). `move_periodic` 은 직선 이동과 겹치지 않아 쓰지 않는다.
- 접근 · 후퇴 · 선 사이 이동은 모두 안전 높이 `z_safe = z_top + travel_clearance_m` 위에서(5절).
- 관제: 웹에서 용접 시작 · 중지 · 안전복귀, 8 선 상태 표시(D9). MQTT `cmd/weld/*` · `weld/*`.
- 스캔과 용접의 배타(D6): 한쪽이 동작 중이면 다른 쪽 시작을 거절(600 · 601).

## 제외 범위
- 실제 아크 용접 · 용접기 연동 · 용접 조건 · 비드 품질 · 열변형.
- 실제 이음 식별(두 부재 사이). 모서리를 이음으로 가정한다.
- **재시작**(D7). 중지 뒤에는 `start_line` 으로 다시 시작한다.
- 힘 · 순응 제어를 쓰는 접촉 추종(심 트래킹).
- 부재 회전 배치 · 여러 부재(1차 BRD 의 MVP 이후 항목 그대로).

# 5. 비기능 요구사항
- **안전**: 힘 · 순응 제어를 켜지 않는다. robot_manager 는 그 제어가 켜져 있으면 `ExecutePath` 를 거절한다(안전망). 경유점 Base z 하한 `path_min_z_m`(출발값 0.100 m) · 속도 상한 `path_max_speed_mps`(0.100 m/s) 를 수락 시점에 본다. safety_monitor 의 과대 외력 · 샘플 최신성 감시는 1차 그대로 동작한다.
- **정확도**: 경유점 도착 허용치 `path_tolerance_m` = ±3 mm(D18 · D32), 자세 허용치 `orientation_tolerance_deg` 15°.
- **1차 규칙 유지**: 실기 명령은 사람이 직접 · 미측정값 0 금지(NaN · `null`) · 수치는 파라미터(`contact_scan_bringup/config/*.yaml` 의 `weld_manager:` 절) · 계약이 코드보다 우선.
- **구성**: 자체 노드 6 개(1차 5 + `weld_manager`). 인터페이스 7 타입 추가(WeldConfig · WeldState · WeldLine · WeldResult · StopWeld · RunWeld · ExecutePath) + `OP_WELD_PATH=5` + ReasonCode 600~604.
