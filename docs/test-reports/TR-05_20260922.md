# TR-05 관제 화면 시험 — 2026-09-22

## 1. 시험 목적

BRD TR-05의 관제 화면 요구사항을 검증한다.

검증 항목:

1. 관제 화면 반영 지연 200 ms 이내
2. 작업 중지 버튼 입력 후 1초 이내 중지
3. 실시간 로그 누락 없음
4. 관제 명령 버튼이 서로 독립된 명령을 호출하는지 확인

추가로 현재 Web UI에 구현된 `안전 해제` 명령의 독립 호출 여부도 확인하였다.

## 4. 관제 화면 반영 지연

측정 경로:

```text
Main PC ROS
   ↓
mqtt_bridge
   ↓
Mosquitto
   ↓
FastAPI
   ↓
WebSocket
   ↓
React Browser
```

MQTT payload의 `published_at_ms`와 Browser WebSocket 수신 시점 `Date.now()`의 차이를 측정하였다.

최종 확인 결과:

```text
scan_id = 20260922-213208-4495

samples = 727
min     = -11 ms
avg     = 2.64 ms
max     = 312 ms

all_under_200_ms = false
```

중간 출력에서도 sample 수는 증가했지만 최대값은 계속 `312 ms`로 유지되었다.

합격 기준:

```text
관제 화면 반영 지연 ≤ 200 ms
```

결과:

```text
312 ms > 200 ms
```

판정: **FAIL**

현재 보존된 측정 결과에서는 312 ms 초과가 존재한다는 사실까지 확인했으나 해당 최대값을 발생시킨 개별 topic은 분리하지 못하였다. 다음 재시험에서는 `topic / scan_id / published_at_ms / received_at_ms / latency_ms`를 함께 기록한다.

| 안전복귀 | `cmd/scan/home` | SUCCEEDED |
| 안전 해제 | `cmd/safety/reset` | SUCCEEDED |

안전 해제 대표 request:

```text
request_id = 97eb6625-29d6-4cb9-86fc-cbbc5582a713

```

시작 명령의 일부 최종 상태가 `FAILED / STOP_REQUESTED`로 기록된 것은 시작 명령 호출 후 TR-05 중지 시험을 수행했기 때문이다. 시작과 중지 topic이 각각 독립 호출된 사실과 구분한다.

판정: **PASS**

## 9. 최종 판정

### TR-05: FAIL — latency 재시험 필요

다음 항목은 통과하였다.

```text
작업 중지 1초 이내   → PASS
로그 누락 없음       → PASS
독립 명령 호출       → PASS
```

그러나 관제 화면 반영 지연에서 최대 `312 ms`가 측정되어 BRD 기준 `≤ 200 ms`를 초과하였다.

따라서 현재 시험 결과만으로 TR-05 전체를 PASS 처리하지 않는다.

## 10. 후속 조치

Main PC와 Web PC가 다시 연결된 환경에서 latency 항목만 재시험한다.

재시험 시 200 ms 초과 샘플에 대해 다음 필드를 반드시 보존한다.

```text
topic
scan_id
published_at_ms
browser_received_at_ms
latency_ms
```

재시험 결과 모든 측정값이 200 ms 이하이면 본 보고서를 최종 PASS로 갱신한다.
