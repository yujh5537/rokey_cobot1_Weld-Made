## 7. 시연 중 `SAMPLE_STALE`(403)로 멈췄을 때의 대응
기준: main `69ae46e`(#161 미머지). 아래 "무엇이 일어나나"는 코드로 확인한 동작이고 실기 재현은 하지 않았다.

**무엇이 일어나나**
1. **움직이는 중**에 `/robot/sample` 이 500 ms 넘게 끊기면 safety_monitor 가 래치(level STOP, 사유 **403**)를 걸고 `/robot/stop` 을 보낸다(`safety_core.SafetyState`). 서 있을 때의 공백은 경고만 남긴다.
2. robot_manager 가 멈춘다. 스텝 모드 밀기 중이었으면 **팁을 들지 않고 그 자리에** 있다(`StepAbort`). 윗면을 누른 채(3~7 N)이거나, 모서리 다듬기 중이면 모서리 바로 밖 윗면 약 0.5 mm 아래다.
3. scan_manager 는 자기가 요청하지 않은 정지라 **ERROR** 로 간다(`sequence.classify`, 사유 403 또는 래치가 늦게 보이면 204). **RESUME 은 STOPPED 에서만 되므로 재개할 수 없다**(`state_machine`).
4. 🔴 **main 의 안전복귀는 올리지 않고 곧바로 OP_HOME(movej)만 보낸다**(`sequence.run_home`). 팁이 부재에 닿아 있으면 모서리를 긁을 수 있다(9/21 #130 과 같은 경로). 안전복귀는 래치 중에도 접수되고, robot_manager 도 남은 정지 요청이 있어도 OP_HOME 은 받는다.
5. START 는 래치 중이면 `SAFETY_LATCHED`(103)로 거절된다. `/safety/reset` 은 샘플이 다시 들어와 조건이 사라져야 통과하고, 로봇을 움직이지 않는다.

**특수한 경우**
- **안전복귀 도중에 걸림**(9/22 748 ms 사례): 이미 공중이면 4 번 불필요. 멈춘 것을 확인하고 5 → 6.
- **반복될 때**(reset 이 계속 거절되거나 2 회 연속 정지): 드라이버 연결 문제 가능성(랜선 · 조회 지연). 그 시연 회차는 **sim 백업 영상으로 전환**한다.
- **웹 중지(사람이 누른 정지)** 는 경로가 다르다: `state_machine` 에서 STOP → STOPPING → STOP_CONFIRMED → **STOPPED** 로 가고, RESUME 은 STOPPED 에서 받는다(단 안전복귀로 움직인 뒤에는 재접근 절차 TBD 로 거절).

**시간 예산**: 복구 1~2 분 + 새 스캔 약 5 분. 9/22 기록으로 스캔 4~5 회에 한 번꼴이라 시연 순서에 **재시도 1 회분(약 7 분)** 여유를 둔다. 리허설에서 3~6 번을 한 번 연습한다(웹 중지로 멈춘 뒤 수동 모드 → 조그 → 자동 모드 → 안전복귀). **목적은 손 순서 익히기다** — 웹 중지는 STOPPED 로 가서 403 의 ERROR 경로와 다르고, 팁이 눌린 채인 상황도 재현되지 않는다(병후 리뷰).
