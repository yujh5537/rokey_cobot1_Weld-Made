## 2. sim 종단 실행 — ✅ **통과 (M2)**

```
$ ros2 action send_goal /scan/run contact_scan_interfaces/action/RunScan "{request_id: 'm2-done'}"
success: true · reason_code: 0 · Goal finished with status: SUCCEEDED
```

Virtual 로봇이 실제로 **기준점 이동 → 하강 → 접촉 → 4방향 밀기 → 형상 계산 → 마무리 홈 복귀**까지 돌았다.

| 항목 | 가상 박스 참값 | 측정 | 오차 |
|---|---|---|---|
| 가로 (x⁺ − x⁻) | 100.00 mm | **99.81 mm** | −0.19 mm |
| 세로 (y⁺ − y⁻) | 60.00 mm | **59.77 mm** | −0.23 mm |
| 높이 (z_top − support_z) | 40.00 mm | **39.86 mm** | −0.14 mm |

`dims_valid` · `box_valid` 모두 true. 마무리 복귀까지 끝나 `RunScan.Result.success=true` 다(계약 7.4).

**이 수치는 sim 모델과 편향 보정 코드가 서로 맞는다는 뜻일 뿐, 실기 치수 정확도의 근거가 아니다.**
sim 박스는 모서리가 수학적으로 예리하고 잡음도 없다. 실기 정확도는 TR-02(T31)에서만 판정한다.

## 2.1 🟠 에뮬레이터 컨테이너가 두 번 죽었다
`sodvir` 의 launch 프로세스는 살아 있는데 **컨테이너가 없는** 상태가 두 번 있었다(`docker ps` 빈 출력. `--rm` 이라 흔적도 없다).
그러면 `dsr_controller2` 노드도 서비스 이름도 다 보이지만 **모든 호출이 무응답**이다. bringup 을 전부 내리고 `ros2 service call` 로 직접 불러도 30초 무응답이었다.

**9/20 `descend_01.csv` 의 "시간 초과 32회"(PR #80)와 같은 증상일 수 있다.** 그때는 드라이버 쪽 문제로 추정했는데, 에뮬레이터 미기동으로도 같은 모양이 나온다. 실기는 원인이 다를 수 있으므로 구분해서 봐야 한다.

- **1차로 죽은 것은 현지의 실수다.** 드라이버 확인 중에 `pkill -f "bringup.launch.py"` 를 썼는데 `sodvir`(`m0609_rg2_bringup/bringup.launch.py`)도 같은 패턴에 걸린다
- 2차로 죽은 원인은 확인하지 못했다

### 📌 통합 절차에 추가
```bash
sod && sodvir
docker ps        # dsr01_emulator 가 보여야 한다. 없으면 드라이버는 무응답이다
```
자체 노드만 내릴 때는 **`pkill -f "source:=sim"`**. `bringup.launch.py` 로 죽이면 `sodvir` 도 같이 죽는다.

## 2.2 🔴 Virtual 기본 자세(관절 전부 0°)는 특이점이다 — 실기에도 걸린다
`/scan/run` 이 `to_origin: 이동이 끝났지만 목표에서 1017.0 mm 떨어져 있다` 로 실패했다. **로봇이 전혀 움직이지 않았다.**

| 시험 | 결과 |
|---|---|
| `move_line` 상대 (SYNC · ASYNC) · 절대 | `success=true` 인데 **posx 변화 없음** |
| `move_joint` J1 +10° | **정상**. J1 0 → 0.1745 rad |
| `get_robot_mode` | 이미 `1`(AUTONOMOUS). 모드 문제 아님 |
| `get_robot_state` | `1`(STANDBY). 상태 문제 아님 |
| **홈 관절각으로 간 뒤 `move_line` 상대 z −50** | **정상.** z 540.6 → 490.6 |

관절이 전부 0° 인 자세는 팔을 위로 쭉 뻗은 **특이점**이라 직선 이동의 역기구학 해가 없다.
드라이버는 `success=true` 를 돌려주고도 움직이지 않는다. `move_joint` 는 관절 공간이라 영향이 없다.

**실기에도 같은 문제가 있다.** 시퀀스는 START 직후 `OP_MOVE_TO` 로 탐색 기준점에 간다. 로봇을 켰을 때 자세가 보장되지 않으므로, 특이점 근처면 그 이동이 **조용히 실패**한다. 지금은 "도착 못 함" 으로만 나와 원인을 알 수 없다.

대응 후보(스탠드업 안건):
- (a) 스캔 시작 전에 사람이 홈으로 보낸다 — **오늘 실기에서는 이것으로 피한다**
- (b) scan_manager 가 START 시 `OP_HOME` 을 먼저 부른다 (병후, 시퀀스 변경)
- (c) robot_manager 가 `move_line` 뒤 실제 이동 여부를 보고 해가 없으면 명확한 사유로 실패시킨다 (학민)

`docs/env/api-check-log.md` 에 "`move_line` 이 `success=true` 인데 움직이지 않는 경우"를 남겨 달라고 학민에게 요청했다(#100).

## 2.3 같이 확인된 것
- `max_descend_m` 을 0.100 으로 뒀더니 scan_manager 가 `INVALID_VALUE` 로 거절했다 — "기준점에서 지지면까지의 거리(0.100)보다 작아야 한다". **맞는 방어다**(팁이 작업대를 뚫는 것을 막는다). 0.080 으로 낮췄다
- `home_joint_deg` 가 두 yaml 에 없어 `OP_HOME` 이 거절됐다(`home: goal rejected`). **형상 계산은 다 되고도 `success=false`** 였다. 계약 7.4 대로 측정 결과 자체는 유효했다
- 실패한 `ScanResult` 는 전부 `NaN` + `*_valid=false` 였다(0 이 아니다). 계약 1장의 무효 값 규칙이 종단에서 지켜진다

## 3. 🔴 잡은 결함: safety_monitor 가 기동하자마자 래치를 걸었다 (#99)
```
[safety_monitor] SAMPLE_STALE: 508 ms 동안 수신 없음 (> 500 ms)
[safety_monitor] /robot/stop 서버가 없다. robot_manager 가 떠 있는지 확인한다
[safety_monitor] 정지 요청이 0.6 s 안에 확인되지 않았다 … 물리 비상정지를 눌러야 한다
```
두 노드의 **보수적 기본값이 겹친** 결과다.
1. 노드 5개가 동시에 뜨면서 샘플이 508 ms 끊겼다(`sample_stale_ms` 500 초과)
2. 그때 robot_manager 는 `moving=true` 였다 — "위치를 모르면 이동 중"(#72). 기동 직후엔 위치 이력이 없으니 당연하다
3. safety_monitor 의 "움직이는 중이면 최신성 조건도 STOP" 이 걸려 래치
4. `/robot/stop` 서버도 아직 없어 `UNCONFIRMED` 까지 올라갔다

`startup_grace_s`(3.0 s)를 넣어 고쳤다. **과대 외력 · 하강 제한은 유예하지 않는다.** 고친 뒤 기동 직후 `level=0`, 래치 없음을 확인했다.

## 5. 오늘 오전 실기 (T30 · T31) — 첫 순서는 탐침 밀림 확인
PR #80 에서 탐침이 홀더 안으로 밀리고 있을 가능성이 나왔다(80분 사이 0.6 → 1.3 mm). **사실이면 그 세션에서 찍은 z 관련 값이 전부 무효다.**

절차:
1. **탐침과 그리퍼 핑거 경계에 펜으로 선을 긋고, 같은 각도로 사진 한 장**
2. 같은 점을 같은 누름 힘(4.5 N)으로 **30초 간격 5회**, 각 회차 시각 기록
   (밀림이 누름 횟수에 비례하는지 시간에 비례하는지가 갈린다 — 대응이 다르다)
3. **끝나고 같은 각도로 사진 한 장.** 0.2~0.3 mm 는 선만으로는 판단이 갈린다. 사진이 유일한 시각 증거다
4. **밀림 확인 결과가 나오기 전에는 다음 단계로 넘어가지 않는다**

그다음 항목: 9/19 작업대 두 점 재측정(작업대 z 가 99.6 인지 100.6 인지 갈린다) · 180° 회전 x · y 확인 · 편향–힘 3점(3 · 5 · 7 N) · 4방향 부호 확인 · 하강–접촉 연속 기록(9/20 `descend_01.csv` 는 z 가 0.06 mm 만 움직여 실패했다).

**2인 1조. 한 사람은 물리 비상정지 버튼에 손을 얹고 화면이 아니라 로봇을 본다.**
9/20 세션은 입회자 없이 진행됐고 같은 세션에서 조회 시간 초과가 32회 있었다(`TR-01_20260920.md`).
