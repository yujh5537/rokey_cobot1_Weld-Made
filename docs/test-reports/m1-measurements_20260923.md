## 1. 도달성 — 확정

판정은 `move_line` 의 `success` 가 아니라 **실측 posx 를 지령과 1 mm 로 비교**한 값이다(아래 4절).

| 줄 | 바깥 방향 | 플랜지 ↔ 베이스 | 결과 |
|---|---|---|---|
| L3 | −x | 426 mm | ✅ |
| L7 | −x −y | 437 | ✅ |
| L4 | −x −y | 546 | ✅ |
| L2 | +y | 587 | ✅ |
| L0 | −y | 644 | ✅ |
| L6 | +x +y | 689 | ✅ |
| **L1** | **+x** | **761** | **❌** |
| **L5** | **+x −y** | **762** | **❌** |

**45° 자세에서 이 로봇의 도달 한계는 플랜지 기준 689~761 mm 사이다.** 명목 900 mm 는 팔을 곧게 뻗은 값이고,
손목을 45° 로 꺾으면 이만큼 줄어든다. 탐침을 바깥으로 기울이면 플랜지가 반대로 252 mm 밀려나므로,
탐침 끝이 큐브 옆 6 mm 에 있어도 플랜지는 큐브 너머로 넘어간다.

### L1 · L5 는 네 가지를 다 시도해 실패

| 시도 | 결과 |
|---|---|
| `movel` 45° | 안 움직임 |
| `movel` 30° (플랜지 738 mm) | 안 움직임 |
| `movejx` sol 0 · 1 · 2 · 3 | 안 움직임 |
| 손목 롤 180° (ZYZ C −180 → 0) | 안 움직임 |

수직(0°)으로 세워도 665 mm 로 경계에 걸린다. **기울기 조정으로는 해결되지 않는다.**

큐브 재배치도 답이 아니다. 로봇 쪽으로 120 mm 이상 당기면 L1·L5 는 살아나지만 L3 의 플랜지가
x ≈ 78 mm 로 로봇 기둥 위에 온다. 90° 회전은 무의미하다 — 큐브의 네 바깥 방향에는 어떻게 놓아도 +x 가 하나 들어간다.
**작업 중간 재배치 또는 회전 테이블이 유일한 해법이다.**

## 2. 간극 — 윗면 확정, 세로 미확정

설계값은 큐브를 직육면체로 두고 팁 구(r 2.5 mm, 중심 = `TCP − r·d`) 표면에서 큐브까지의 거리로 계산했다.
스탠드오프 오프셋이 모서리 이등분선(= 탐침 축) 방향이라 **스탠드오프 값이 그대로 간극이 된다.**
(윗면 위 자세는 최근점이 꼭짓점이라 6.00, 세로선 아래 자세는 최근점이 수직 모서리라 z 성분이 안 세어 3.51.)

### 윗면 모서리 (스탠드오프 3) — 확정

```
실측 5.0 · 5.0 · 1.5 · 2.0 · 3.0 · 5.0      평균 3.58      설계 3.00
```

설계값을 중심으로 흩어져 있고 계통 편차가 없다. 편차 ±2 mm 는 줄자 눈금(1 mm) 한계 안이다.
**스탠드오프 3 mm 설계는 이것으로 검증됐다.**

### 세로 모서리 (스탠드오프 6) — 사용 불가

```
실측 1.1 · 0.8 · 0.5 · 0.4 · 0.4 · 0.5   설계 6.00(위) / 3.51(아래)
단, L7 bottom 만 9.0
```

여섯이 설계의 1/10 쪽이고 하나만 2.5 배다. **줄자 오차로는 이 폭이 나오지 않는다.**

같은 꼭짓점을 잰 두 값이 역방향으로 벌어진다는 점이 결정적이다:

| | 스탠드오프 | 설계 | 실측 |
|---|---|---|---|
| L0 start | 3 | 3.00 | 5.0 |
| L4 top | 6 | 6.00 | 1.1 |

두 자세는 같은 꼭짓점 (377.87, −199.05, 177.77) 주변이다. **스탠드오프를 두 배로 올렸는데 실측은 1/5 로 줄었다.**
큐브 좌표 오차·탐침 길이 오차·TCP x·y 오차는 모두 두 값을 같은 방향으로 움직이므로 이 역전을 설명하지 못한다.

배제한 것:
- **TCP x·y = (0, 0)** — 팁을 십자 위에 놓고 J6 을 180° 돌렸을 때 팁이 0.03 mm 안에서 제자리였다
  (`docs/env/tool-tcp-register.md` 9절, #137). `(−1.30, 3.71)` 은 교체 전 옛 탐침 값이다
- **큐브 좌표** — 자세가 큐브 좌표에 상대적으로 정의되므로 좌표를 바꿔도 설계 간극은 불변이다
- **탐침 길이** — 오차가 툴 축 방향이라 두 그룹에 같은 양으로 작용한다

L4 top 에서 나올 수 있는 거리를 다 따져도 0.4~1.1 mm 에 해당하는 것이 없다:

```
꼭짓점까지 대각선  6.00      윗면까지 수직  4.24
−x 면까지 수평     3.00      −y 면까지 수평  3.00
```

세로 자세는 탐침이 꼭짓점을 비껴 대각선으로 서기 때문에 측정 지점을 눈으로 잡기 어렵다.
**측정 방식 문제로 보고, 캘리퍼 재측정 전까지 미확정으로 둔다.**
0.4 mm 를 그대로 적으면 "탐침이 큐브에 닿기 직전이었다"는 잘못된 결론으로 이어진다.

재측정은 L4 · L7 두 줄(4 자세)만 캘리퍼로 하면 되고 20 분이면 끝난다.

## 4. 측정 중 드러난 스크립트 결함 두 개 (이 브랜치에서 수정)

### (a) `reach` 가 거짓이었다

두산 `move_line` 의 `success` 는 "명령을 받았다"이지 "그 자세를 만들었다"가 아니다.
L1 은 로봇이 한 번도 안 움직였는데 `success=true` 가 돌아와 `reach=1` 로 기록됐다.
`move_jointx` 도 같다 — 도달 불가 자세에 8 회 연속 `success=true` 를 돌려줬다.

수정: 실측 posx 와 지령을 위치 3 성분만 1 mm(`ARRIVE_TOL_MM`)로 비교한다.
자세(ZYZ)는 `(A, B, C)` ≡ `(A+180, −B, C+180)` 두 표현으로 오므로 비교에서 제외했다
(지령 `[−90, 135, −180]` 에 응답 `[89.99, −135.00, −0.01]` 이 왔다).

`motion/ikin` 은 쓰지 않았다 — sol 0~7 전부 `success=true` 에 J2 = 29914° 같은 값을 돌려준다.

### (b) 자세 사이 안전 높이가 없어 큐브와 충돌했다

세로선은 목표 위 30 mm 가 여전히 큐브 옆구리다.
L4 bottom 을 마치고 30 mm 올린 자리가 z = 151.25 였고(윗면 177.77 보다 26 mm 아래),
거기서 L6 로 직선 이동을 걸자 경로의 3.5 % 지점에서 큐브 안(z ≈ 153)으로 들어갔다. **실제로 부딪쳤다.**

수정: `--safe-z`(기본 = 큐브 윗면 + `--lift`)를 넣고
**수직 상승 → 안전 높이에서 수평 이동·회전 → 수직 하강** 3 단계로 바꿨다. 실패해도 안전 높이로 물러난다.
